# ADR-0009: Explorer "Always keep / Free up space" verbs via a one-time elevated setup that writes SyncRootManager Flags

## Status

Accepted 2026-11-14 on the user's instruction ("I don't see a problem with the installer step running as admin, if that doesn't generate other problems or make things more complex or at risk of being unstable"). Provisional: the stability conditions below must be re-verified in P1, and the decision is revisited if package identity (sparse package) proves simpler.

## Context

Measured on the user's PC (Windows 11 26H2 build 26300.9974), see `research/cfapi.md` ("SyncRootManager Flags experiments"):

- An unpackaged `StorageProviderSyncRootManager.Register` writes `Flags=34` (0x22). With 34 Explorer shows **no** "Always keep on this device" / "Free up space" verbs, a **blank Status column** and a generic brown-box icon on online-only files.
- Setting `Flags=2` makes the plain Status column work and removes the brown icons, but there are still no verbs.
- Setting `Flags=1058` (0x422, OneDrive's own value) makes the **verbs appear** (0x400 together with 0x20).
- No `StorageProviderSyncRootInfo` property produces 0x400 (probe over `ProtectionMode`, `RecycleBinUri`, `AllowPinning`, item property definitions; `ShowSiblingsAsGroup` only adds 0x200).
- **Re-running `Register` on an existing root resets `Flags` to 34**; stopping and reconnecting the provider does not change it.
- The SSH session of the user's PC is an elevated administrator token, so writing the key works from an elevated process; a normal non-elevated process cannot write HKLM.
- `Flags` is undocumented by Microsoft; Nextcloud writes 34/2 (research/cfapi.md).

## Decision

1. Sync-root registration becomes an **install-time, elevated** operation performed by a small setup step (`NoDrive.Engine.exe --setup`, UAC prompt, or the installer): `StorageProviderSyncRootManager.Register(...)`, then set `Flags` to 1058 on our own `SyncRootManager\<id>` key, then optional policy/namespace housekeeping. It runs once per account/root.
2. The always-on engine **never calls `Register` at start-up**; it only calls `CfConnectSyncRoot`. A re-registration (settings change, repair) goes through the same elevated step.
3. At every start the engine reads `Flags` (read access to HKLM is unprivileged). If it is not 1058 it keeps working (sync is unaffected) and shows a tray notice "Windows context-menu integration needs repair" whose action relaunches the elevated setup. It never loops or blocks on this.
4. Uninstall calls `StorageProviderSyncRootManager.Unregister` (elevated) after offering to hydrate everything, as already decided for `CfUnregisterSyncRoot`.
5. Status column and icons: with 0x20 set and no per-file state handler Explorer shows a blank Status and the brown box. To be settled in P1/P2 by either a `CustomStateHandler` COM server, package identity, or accepting the generic look. Pin/free-up also remain available from the tray menu regardless.

## Consequences

Positive:
- Native Explorer verbs without writing a shell extension or giving the app package identity; consistent with how OneDrive itself is registered.
- Setup is a single, well-defined elevated action; the daemon stays unelevated (matches the requirement that the provider must not be elevated).

Negative / risks:
- Relies on an **undocumented** registry value. A Windows update could change its meaning or reset it. Mitigation: read-only check at start-up + tray repair action; CI/spike re-test on each Windows build we support.
- Any code path that calls `Register` again silently drops the flag. Mitigation: design rule (2) and a test that fails if the engine process imports `Register`.
- Needs UAC at install/repair; a per-user install without admin rights gets Flags 34 behaviour (no verbs) and falls back to the tray menu.
- Status column / icons are not solved by this decision.

Revisit when: Windows documents the flag; a Windows update resets or ignores it in testing; the package-identity spike shows the verbs and Status with `Register` alone; the user's install cannot obtain admin rights.
