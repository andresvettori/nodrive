# ADR-0014: Microsoft Store distribution as MSIX with removal clean-up helper

## Status
Accepted (2026-11-19)

## Context
The Store rejected the unsigned MSI (policy 10.2.9). An MSIX is signed by the Store. MSIX has no uninstall hook; update and removal both send WM_QUERYENDSESSION, WM_ENDSESSION (flags 0x1, ENDSESSION_CLOSEAPP) and WM_CLOSE, while shutdown, restart and logoff do not carry 0x1. Anything the package starts is killed on removal. `StorageProviderSyncRootManager.Unregister` and `CfUnregisterSyncRoot` (0x8007007B) fail from outside the package for a root registered inside it.

## Decision
Ship a full-trust MSIX ("NoDrive Client", runFullTrust, startup task for autostart) next to the GitHub MSI. On close with flags 0x1 and nothing pending the engine starts a copy of itself from %TEMP% through Task Scheduler (`--cleanup-after-removal <PFN>`); the helper unregisters the sync root only if the package stays absent about a minute, deleting the HKLM sync-root key as last resort. A page button "Prepare to uninstall" does it on demand. Connecting to a stale registration (0x80070186) re-registers once.

## Consequences
Measured on the test PC with a loose-registered package (update: no action; removal: key gone). Not yet verified with a real Store install, where the OS may unregister by itself; startup-task autostart unverified.
