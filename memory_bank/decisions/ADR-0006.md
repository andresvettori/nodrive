# ADR-0006: MIT licence for NoDrive; permissive sources only; GPL projects as read-only references

## Status

Accepted 2026-11-13

## Context

NoDrive may reuse open-source code where the licence allows. The research produced a licence map of the relevant projects; the choice of NoDrive's own licence determines which of them can be copied.

### Other

- KoenZomers/OneDriveAPI is EPL-1.0 (weak, file-level copyleft); SimpleList has no licence file and cannot be used at all. Source: https://github.com/KoenZomers/OneDriveAPI , https://github.com/aiguoli/simplelist
- Apache-2.0 code can be included in an MIT project provided the Apache NOTICE/attribution requirements are met; 0BSD needs no attribution.

### Considerations

- The user's stated preference is a personal tool that may be shared; MIT keeps commercial and closed-source options open and is the licence of the most useful references (rclone, CloudMirror).
- GPL-3.0-or-later would unlock copying from Nextcloud/ownCloud (the most battle-tested cfapi code) and PrimalZed/CloudSync, and would qualify for the WinFsp exception, but the mount fallback is not needed (ADR-0001) and the cfapi protocol knowledge in those projects is fully recoverable from Microsoft's API documentation and the MIT CloudMirror sample.
- Code signing / SmartScreen is a distribution concern independent of licence; decide when NoDrive is first shared outside the author's machine. Source: https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps

## Decision

NoDrive is released under the MIT licence (`LICENSE` at the repo root). Only code from MIT, BSD/0BSD and Apache-2.0 projects may be copied or ported, with attribution kept in a `THIRD-PARTY-NOTICES.md`. GPL and other copyleft projects are read for protocol and behaviour knowledge only; re-implement from Microsoft's API documentation, never copy code, data tables or comments from them. Projects with no licence are not used.

Rules that follow:

- Every ported snippet carries a comment with the origin project, file, commit and licence, and an entry in `THIRD-PARTY-NOTICES.md`.
- Apache-2.0 ports keep the required NOTICE text; 0BSD needs none; MIT needs the copyright line.
- When reading a GPL source to understand a cfapi flag or registry layout, write down the learned fact and its Microsoft documentation URL in `memory_bank/research/`, not the code.
- Dependencies are restricted to permissive licences; no LGPL dynamic linking is currently needed (Dokany is not used).

## Consequences

### Positive

- All of rclone's OneDrive protocol logic and Microsoft's CloudMirror architecture are freely portable.
- Compatible with any future distribution model (personal, open source, commercial, Microsoft Store).
- Simple compliance: attribution only.

### Negative

- The most mature cfapi implementations (Nextcloud, ownCloud) are off limits for copying; their lessons must be re-derived and re-tested.
- The WinFsp FLOSS exception is unavailable, which rules out a WinFsp mount fallback unless commercially licensed (irrelevant under ADR-0001).
- MIT gives no patent grant to users; acceptable for a personal tool.

### Revisit when

- A mount fallback via WinFsp becomes necessary (then GPL-3.0-or-later would be the pragmatic choice).
- NoDrive wants to merge substantial GPL code rather than re-implement it.
- A contributor or distribution channel requires a different licence.
