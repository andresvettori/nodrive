# ADR-0004: Hand-written Graph client (HttpClient + System.Text.Json source-gen) instead of the Microsoft.Graph SDK

## Status

Accepted 2026-11-13

## Context

NoDrive talks to a personal OneDrive through Microsoft Graph v1.0. The surface actually needed is about ten endpoints: `GET /me/drive`, `GET /me/drive/root/delta` (initial, `token=`, `token=latest`), `GET /me/drive/items/{id}` with `$select`, `GET .../content` or `@microsoft.graph.downloadUrl` with `Range`, `PUT .../content`, `POST .../createUploadSession` + fragment `PUT`s to `uploadUrl`, `PATCH` (rename/move), `DELETE`, `POST .../permanentDelete` (optional), `POST .../children` (folder create), `GET /me/drive/root/subscriptions/socketIo` (P2), `GET .../thumbnails` (P2).

### Evidence against the SDK

- Microsoft.Graph 6.10.0 (NuGet 2026-11-09) is a 52.61 MB nupkg targeting netstandard2.0/2.1, net8.0, net10.0; it pulls Microsoft.Graph.Core 4.0.1, seven Kiota 2.x packages, Microsoft.IdentityModel.* 8.18 and transitively Azure.Core. `IsTrimmable=true` but no `IsAotCompatible`. Source: https://www.nuget.org/packages/Microsoft.Graph , https://github.com/microsoftgraph/msgraph-sdk-dotnet/blob/main/src/Microsoft.Graph/Microsoft.Graph.csproj
- Open issues: #2944 `PageIterator` throws when trimmed (since 2025-07, no response); #1702 DLL size acknowledged, splitting declined; a dotnet/runtime issue documents ILLink taking very long on Microsoft.Graph. Maintainers themselves point size-constrained apps to Kiota-generated or hand-written clients. Source: https://github.com/microsoftgraph/msgraph-sdk-dotnet/issues/2944 , https://github.com/microsoftgraph/msgraph-sdk-dotnet/issues/1702 , https://learn.microsoft.com/en-us/graph/sdks/sdks-overview
- No official statement of Native AOT support for the SDK was found; Kiota 1.16 "no longer crashes the AOT compiler" is community-reported.
- The SDK has no first-class request builder for the `socketIo` endpoint (the docs' C# sample calls a generic subscriptions builder). Source: https://learn.microsoft.com/en-us/graph/api/subscriptions-socketio?view=graph-rest-1.0
- Microsoft CSS does not support the SDKs, only the HTTP API.

### Evidence that the raw client is sufficient

- Every endpoint, limit and quirk is documented at the HTTP level: delta semantics (track by id, last occurrence wins, consumer deletes omit `ctag`/`size`, 410 Gone resync codes), upload sessions (320 KiB multiples, < 60 MiB per PUT, no `Authorization` header on fragment PUTs, 404 = restart, `conflictBehavior` default `fail` for sessions vs `replace` for simple PUT), downloads (`downloadUrl` ~1 h, `Range` -> 206 or 200), throttling (`Retry-After` on 429/503 only), hashes (`quickXorHash` only). Sources: https://learn.microsoft.com/en-us/graph/api/driveitem-delta?view=graph-rest-1.0 , https://learn.microsoft.com/en-us/graph/api/driveitem-createuploadsession?view=graph-rest-1.0 , https://learn.microsoft.com/en-us/graph/api/driveitem-put-content?view=graph-rest-1.0 , https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0 , https://learn.microsoft.com/en-us/graph/api/resources/hashes?view=graph-rest-1.0 , https://learn.microsoft.com/en-us/sharepoint/dev/general-development/how-to-avoid-getting-throttled-or-blocked-in-sharepoint-online
- rclone's `backend/onedrive` (MIT) is a complete production reference for the same protocol, including QuickXorHash and restricted-character handling. Source: https://rclone.org/onedrive/
- System.Text.Json source generation (Metadata mode) supports streaming `DeserializeAsync` over large delta pages and is the documented AOT-safe path. Source: https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/source-generation
- Memory goal: a single static `HttpClient` over `SocketsHttpHandler` with `PooledConnectionIdleTimeout` 20-30 s, `ResponseHeadersRead` streaming into `CfExecute`/`FileStream` with `ArrayPool` buffers; no SDK middleware pipeline, no buffering of whole bodies.

### Alternative considered: Kiota-generated client limited to `/me/drive/**`

- `kiota generate --include-path "/me/drive/**"` with a custom `IAuthenticationProvider` produces a smaller client compatible with Microsoft.Graph.Core helpers, but still brings the Kiota abstractions/serialization packages and the unverified AOT story. Reasonable fallback if the endpoint count grows well beyond ten. Source: https://learn.microsoft.com/en-us/graph/sdks/generate-with-kiota

## Decision

`NoDrive.Graph` is a hand-written client: one static `HttpClient` over a configured `SocketsHttpHandler`, hand-written DTOs for the `driveItem` subset, delta page, upload session, error payload and thumbnails, all in one `[JsonSerializable]` `JsonSerializerContext` (Metadata mode, `JsonStringEnumConverter<T>` where needed), a central throttle gate that honours `Retry-After` for every worker, an `IRemoteDrive` abstraction consumed by `NoDrive.Core`, and a separate `IContentTransfer` seam for download/upload URLs (the name used in `systemPatterns.md` and `bestPractices.md`). No Microsoft.Graph, no Kiota, no Azure.Identity.

Rules that follow:

- `User-Agent: ISV|<You>|NoDrive/<version>`; `$select` on every list/delta call; persist `nextLink`/`deltaLink` after every page.
- One global `Retry-After` gate: on 429/503 all Graph work pauses for the given seconds (capped and surfaced to the tray); exponential backoff with jitter for other transient failures.
- Explicit `@microsoft.graph.conflictBehavior` on every write; `If-Match` eTag on every update; fragments 5-10 MiB multiples of 320 KiB streamed from disk; no `Authorization` header on `uploadUrl`/`downloadUrl` requests.
- Downloads: fetch `downloadUrl` per hydration, refresh on 401/403 or age > 50 min, accept 206 or 200, verify size and `quickXorHash` while streaming.
- Never call `sharedWithMe` or `recent` (deprecated, stop returning data after Nov 2026).
- The transfer layer is isolated so the 2027-04-01 tempauth URL retirement (MC1492958) can be absorbed by switching to bearer `GET /content`.
- Every DTO change updates the fake Graph server used by the tests.

## Consequences

### Positive

- Tens of KB of code instead of a 52 MB dependency tree; AOT-clean by construction; fast ILLink.
- Full control over streaming, buffering, timeouts and cancellation, which the "never hang Explorer" and memory requirements need.
- The fake Graph server (fault injection, 500k-item delta) is trivial to build against the same DTOs.

### Negative

- We maintain the DTOs and must read the docs for every endpoint; Graph additions are manual.
- No SDK helpers (`PageIterator`, `LargeFileUploadTask`); chunking and paging are our code and our bugs.
- Undocumented consumer behaviours (delta `@removed`, folder `cTag` on personal, `$top` honoured page size) must be verified empirically.

### Revisit when

- The endpoint count grows well beyond ~15 (then evaluate a scoped Kiota client).
- Microsoft publishes an officially AOT-compatible, modular Graph SDK of a few MB.
- Microsoft changes the HTTP contract in a way that an SDK absorbs and we cannot keep up with.
